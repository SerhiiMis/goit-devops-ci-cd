Lesson 7: Kubernetes Cluster with EKS, Terraform, and Helm

Цей проект розгортає Kubernetes кластер (EKS) на AWS, налаштовує репозиторій ECR та автоматично деплоїть Django-застосунок за допомогою Helm.

Структура проекту

main.tf - Головна конфігурація Terraform (провайдери, модулі, Helm реліз).

modules/ - Локальні модулі Terraform:

eks - Налаштування кластера EKS та робочих нод.

vpc - Мережева інфраструктура.

ecr - Реєстр контейнерів.

s3-backend - Зберігання стейту Terraform.

charts/django-app - Helm-чарт для застосунку (Deployment, Service, HPA, ConfigMap).

Передумови

Для запуску проекту необхідні встановлені інструменти:

Terraform >= 1.6.0

AWS CLI v2

Helm (опціонально для локальної перевірки)

Як запустити

Ініціалізація Terraform:
Завантаження необхідних провайдерів та модулів.

terraform init


Перевірка плану (опціонально):

terraform plan


Розгортання інфраструктури:
Ця команда створить VPC, EKS, ECR та задеплоїть Helm-чарт.

terraform apply -auto-approve


Час виконання: приблизно 10-15 хвилин.

Отримання посилання на застосунок:
Після успішного деплою отримайте DNS-ім'я Load Balancer:

aws elbv2 describe-load-balancers --region us-west-2 --query "LoadBalancers[*].DNSName" --output text


Відкрийте отримане посилання у браузері.

Очищення ресурсів

Щоб уникнути зайвих витрат, видаліть створені ресурси після перевірки:

terraform destroy -auto-approve


Особливості реалізації

EKS: Кластер версії 1.30 з публічним доступом до API.

Nodes: Група нод використовує інстанси t3.small у публічних підмережах для забезпечення доступу до інтернету без NAT Gateway (оптимізація витрат).

Helm: Використовується провайдер hashicorp/helm з методом аутентифікації exec для надійного отримання токена доступу до кластера.
